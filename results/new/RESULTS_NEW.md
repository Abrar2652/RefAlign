## 1. Experiment 2: sensitivity of the prediction to the choice of reference (LLM-free)

**Design as run.** The four human-labeled families (`annotation/traces_scale`, gold = `results/human_perrun.json`, verified identical to `annotation/annotations_human/adjudicated`). For each of the 32 failing runs, every successful run of its family was forced to be the reference by monkeypatching `refalign.contrastive._nearest_sibling`; `contrastive_localize` itself ran unmodified with the default configuration (sibling='content', tau=0.9, top_k=4). Forcing the method's own nearest reference reproduces its own prediction on all 32 runs (asserted). A reference "follows the same arithmetic path" when the Jaccard overlap of its normalised Worker CALC expressions with the failing run's is at least 0.5. Correlations are point-biserial between a reference-to-failing distance (`_sibling_distance`, edit and content) and step correctness over all 156 (failing run, reference) pairs. Intervals are 95% Wilson; the single paired test is an exact McNemar with no correction (one test).

**Result.** The predicted step is invariant to the reference for 32/32 runs (95% Wilson [0.89, 1.00]); nearest, first, random, best and worst reference all give exact-step 0.469 (15/32, [0.31, 0.64]). Nearest vs first (the annotators' view): b=0, c=0, p=1.000. The nearest reference coincides with the first one in 1/5 (t00), 5/5 (t05), 0/11 (t07) and 3/11 (t09) runs, so the two selection rules differ often yet never change the answer.

**On the paper's t07 explanation.** No successful t07 run follows the failing runs' arithmetic path (0 of 11 failing runs have a same-path reference; 0 same-path pairs). All three references use the two-step decomposition `600*(1-0.15)`, `510*(1+0.10)`; every forced reference yields the same fallback prediction (Verifier, terminal step) and exact-step 0.00. The hypothesis that a same-path reference would recover the human step therefore cannot be tested on the released data; what the data do show is that the miss is not a reference-selection error, since no available reference fixes it. Pooled over families, same-path pairs are correct 18/38 vs other-path 69/118 (Fisher p=0.263): sharing the arithmetic path does not help either.

**Distance and correctness.** Pooled over 156 pairs, step correctness correlates negatively with edit distance (point-biserial r=-0.49, p=<0.001) and content distance (r=-0.41, p=<0.001). This is a between-family effect (t07 has the largest distances and zero correctness): within families, real_t00: edit r=-0.70 (p=<0.001), content r=-0.47 (p=<0.001), 45 pairs; real_t05: correctness constant across all 45 pairs (no correlation defined); real_t07: correctness constant across all 33 pairs (no correlation defined); real_t09: edit r=-0.11 (p=0.533), content r=+0.49 (p=0.004), 33 pairs. Because the prediction is invariant to the reference within a run, no within-run distance effect exists at all.

**Reading.** On this benchmark the choice among available references is irrelevant; RefAlign's errors are family-level structural mismatches (t07, t00 loops), not unlucky sibling picks. The "different valid strategy" concern is real for t07 in the sense that all references use a different decomposition, but it cannot produce a different prediction here because the count-consistent backbone collapses every reference to the same alignment.

## 2. Experiment 1: the matched-information LLM judge

**Design as run.** Cells: length gradient L in {5, 12, 24, 40} (`build_population(None, t, L, seed=0, noise=True)`, 6 tasks, 24 failing runs each), multi-culprit L=12 (`build_multiculprit(t, 12, seed=0, n_fault=8)`, n=48), reorderable sum k in {8, 15} (`build_diverse(t, k, seed=0)`, n=36 each), and the 32 human-labeled failures scored against `human_perrun.json`. Methods on identical runs: RefAlign (`contrastive_localize`, no LLM); single-trace All-at-Once (`all_at_once`, unchanged); matched judge (`matched_judge`, appended to `llm_baselines.py`) with reference = RefAlign's selected sibling (`matched-phylo`), a uniformly random successful run with seeds 0..4 (`matched-random`, mean and range over seeds), or `successes[0]` on the human cell (`matched-first`). The matched prompt renders both runs with `contrastive_llm`'s 120-character step format and asks for `STEP: <failing step index> | AGENT: <agent name>` (zero-based). Answers go through the existing parser plus one tolerance: `gpt-4o-2024-08-06` writes the index in brackets (`STEP: [2] | AGENT: Worker`, mirroring the `[i]` rendering of the prompt), which the strict regex rejects, so every stored judge answer of every judge and method was re-parsed accepting a bracketed index (`experiments/reparse_judge_outputs.py`); the strict-parser counts are kept alongside. An answer with no `STEP` token at all is scored incorrect on both metrics and counted (never mapped to the last step). Scoring follows `run_contrastive._score`. Judges: `gpt-4o-mini-2024-07-18` (primary) and `gpt-4o-2024-08-06` via the OpenAI API with `seed=0`-style per-call seeds and logged fingerprints, plus the six open models of the paper served locally; all at temperature 0, `max_tokens` 128 (R1: 1536). Judge rows appear in the order they were run. Statistics: 95% Wilson intervals; exact binomial McNemar on paired exact-step outcomes for RefAlign vs matched-phylo and matched-phylo vs AAO; Holm-Bonferroni within the family of the four length cells per judge and comparison (m=4); the multi-culprit, reorder and human cells are single tests reported uncorrected; Cohen's h.

## 6. Experiment 4B: Who&When re-sampling (not attempted)

Not attempted, for three reasons that make a reproducible run impossible here. First, the Who&When traces were produced by CaptainAgent and Magentic-One (AutoGen) driving GPT-4-class OpenAI models over live web browsing, code execution and file tools; the original model snapshots (`gpt-4-turbo` / `gpt-4o` of early 2025) cannot be requested any more, so a re-sample would be a different system on a different model, not a re-run of the benchmark's generator. Second, the queries depend on external state (GAIA web pages and downloadable files as of the original run); ten re-runs per query would face changed pages and dead links, so run-to-run differences would mix agent stochasticity with environment drift, which is exactly what a population must not do. Third, the AutoGen framework versions used are not pinned in the released data. A partial version with a local open model on a subset of offline-solvable queries would answer a different question and was not attempted, as the brief instructs.

## 8. Deviations from the brief and failures, in full

1. **Two-phase session.** OpenAI credit was exhausted at the start; all experiments were first run on local open models (six judges; Qwen2.5-7B-Instruct as agent). After credit was added the OpenAI-specified runs were executed in full and are the primary results; the local runs are kept as supplementary (Sections 2, 3.1, 4.1, 5.1). Anthropic keys were available and unused (not in the brief; one key belongs to another project).
2. **Experiment 4A used `max_worker_turns=8`** (default 5) so GSM8K chains can finish; recorded in the design block, same for both agent models.
3. **Experiment 5's semantic system is new code** (`experiments/semantic_agents.py`); its action parser accepts the keyword without a colon. The local run was done twice: the first pass with a colon-requiring parser mis-read NOTE lines and is kept under `results/new/logs/`; the gpt-4o-mini run used the final parser only.
4. **gemma-2-9b-it rejects a system role**; the logged client merges the system prompt into the user message for that judge only (flag `system_merged_into_user`). Two gemma launches aborted before this fallback was thread-safe; their failed attempts remain in the API log as error lines.
5. **DeepSeek-R1-Distill was run as three processes** on three servers over disjoint cell subsets after a first single-process run was stopped at 276 calls for speed; pieces were merged per run, its judge metadata in `matched_judge.json` reflects the last merged part, and its call totals (including the stopped run) come from the API logs. Each piece crashed in its final console summary (a `KeyError` on cells it had not run) *after* saving all outcomes; the print loop has since been made tolerant of partial runs.
6. **The local Experiment 3 usage block** was recomputed from its API log after an analysis-only rerun dropped the in-memory tally.
7. **The ">2,000 API calls" pause**: local runs were free and did not pause; the OpenAI runs (largest: Experiment 4A, about 4,800 gpt-4o-mini calls) were launched after the user confirmed that credit was loaded, and their costs are in Section 7.
8. **Sampling-defaults trap avoided, not hit:** vLLM adopts the model's Hugging Face generation config unless `--generation-config vllm` is passed; every local server used it, and the one server started without it was restarted before any call.
9. **File naming.** The gpt-4o-mini runs carry the brief's file names (`intervention.json`, `external_gsm8k.json`, `semantic_variant.json`, `annotation/external_pending/`, `annotation/semantic_pending/`); the local runs carry a `_qwen2.5-7b` suffix.
10. **Bracketed step indices.** `gpt-4o-2024-08-06` answered `STEP: [k]` in 1105 matched-judge calls (all `finish_reason=stop`, about 10 completion tokens), which the existing strict regex rejects. Rather than score a correctly formatted answer as wrong, `parse_judge_answer` accepts a bracketed index and all stored outputs of all judges and both judge methods were re-parsed offline from their saved raw text; strict-parser counts are retained in `matched_judge.json` (`n_unparsed_step_strict`) and reported next to the tolerant counts. Outputs with no STEP token (R1 truncations) stay unparseable.
